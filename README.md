# 今天吃什么（WTE）

一个纯离线的 Rust 桌面小工具：**5 个问题，从 118 道外卖主食里挑一道**。

不做饭、只点外卖，但每天站在菜单前发呆？让它替你选。**不显示预估价格**，价格请以下单平台为准。

## 特性

- **5 道单选题**：早饭/午饭/晚饭、甜口/咸口、带汤/不带汤、饭/面/其他主食、辣度；每题都能选「都行」跳过
- **点选项自动进下一题**，同时保留「上一步 / 下一步」，想改答案随时退回
- **结果一定是主食**：饭、面、粉、汉堡、炸鸡、饺子、麻辣烫……不会给你推奶茶或甜点
- **条件太苛刻也一定有结果**：按「辣度 → 汤水 → 口味 → 餐段」逐级放宽，**主食维度永不放宽**，并在结果页注明放宽了什么
- **「换一个」不重复**：避开最近 10 次抽到的菜
- **可接自己的外卖菜单**：在 exe 同目录放一个 `menu.txt`，把附近能点到的菜写进去，就能按真实菜单筛选
- **完全离线**：无网络请求、无 WebView、无后台服务、无遥测；断网、无浏览器环境也能跑
- **轻量**：release 单个 exe 约 3 MB，启动即用

## 运行

需要 Rust 1.85+（本项目用 1.97 开发，eframe 0.32）。

```powershell
cargo run --release
```

发布构建：

```powershell
cargo build --release
# 产物位置由 cargo 配置决定；本项目在 Windows + 中文用户名环境下
# 默认写到 C:\Users\Public\rmcl-target\wte\release\wte.exe
```

> 本机备注：用户名含中文时，mingw 的 `dlltool.exe` 无法处理中文路径。
> 已在全局 `~/.cargo/config.toml` 中把 target-dir 指到 ASCII 路径，并用 `rust-lld` 作为链接器。
> 换机器后如果遇到 `dlltool ... Can't create .lib file`，给 cargo 指定一个纯英文路径即可：
> `cargo build --release --target-dir C:\rust-target\wte`。
>
> target-dir 只存放编译缓存，不含任何项目文件或用户数据；`menu.txt` 永远写在
> **项目根目录**（开发时）或 **exe 同目录**（发布版）。

### 分发时注意完整性标签

如果 exe 是从带沙箱/低完整性标签的目录复制出来的，双击后会以 **Low 完整性**运行，
此时「打开所在文件夹」会被 Windows 拒绝（`ShellExecuteW 失败（代码 5）`）。
发布前确认：

```powershell
icacls dist\wte.exe
# 应显示 Mandatory Label\Medium Mandatory Level

# 如果显示 Low，执行：
icacls "dist" /setintegritylevel "(OI)(CI)Medium"
icacls "dist\wte.exe" /setintegritylevel Medium
```

应用内「菜品库」页面也会显示当前运行环境完整性，正常应为 Medium。

## 使用

1. 双击 `wte.exe`，点「开始选」；
2. 依次回答 5 个问题（点选项会自动进入下一题）；
3. 结果页给出菜名、餐段/口味等标签、一句话提示，以及几个备选；
4. 「换一个」重新抽，「重新选」回到第一题。

### 自定义菜单

点「菜品库 / 自定义菜单」→「生成菜单模板」，程序会在 **项目根目录**（`cargo run` 开发时）
或 **exe 同目录**（发布版）生成 `menu.txt`，也可以自己创建：

```text
# 名称 | 口味(甜/咸/皆) | 汤水(汤/干/皆) | 主食(饭/面/其他) | 辣度(0-2) | 餐段(早/午/晚/皆) | 备注
黄焖鸡米饭|咸|干|饭|1|皆|我家楼下这家微辣刚好
八宝粥|甜|汤|饭|0|早|甜口暖胃
部队锅|咸|汤|其他|1|晚|一个人也能吃
```

规则：

- 一行一道菜，`|` 分隔；`#` 或 `//` 开头是注释，空行忽略
- 餐段：写「早」只在早饭出现，写「晚」只在晚饭出现，写「皆」表示全天
- 与内置题库同名的菜会**覆盖**内置条目（适合改口味、餐段、备注）
- 解析失败的行会被跳过，并在菜品库页面显示「第几行、什么原因」，不影响其他菜

程序启动时按 **当前目录 → exe 同目录 → 开发时的项目根目录** 的顺序查找 `menu.txt`。

## 项目结构

```
WTE/
├─ Cargo.toml
├─ README.md               # 项目入口
├─ assets/
│  ├─ menu.txt             # 内置题库（编译进二进制）
│  └─ menu.sample.txt      # 自定义菜单模板
├─ docs/
│  ├─ PLAN.md              # 方案计划书
│  └─ NOTES.md             # 实现决策记录
├─ src/
│  ├─ main.rs              # 入口、窗口配置
│  ├─ app.rs               # egui 界面与状态机
│  ├─ lib.rs               # 核心逻辑入口（可单测）
│  ├─ model.rs             # 菜品与标签枚举
│  ├─ menu.rs              # 内置题库、menu.txt 解析与合并
│  ├─ quiz.rs              # 问题、筛选、放宽、随机推荐
│  └─ rng.rs               # 无第三方依赖的 xorshift 随机数
└─ dist/
   └─ wte.exe              # release 构建产物
```

核心逻辑不依赖 egui，`cargo test` 不会启动窗口。

## 测试

```powershell
cargo test
```

覆盖：菜单解析（坏行、重复、餐段列）、内置题库完整性、餐段/口味/汤水/主食/辣度组合、放宽顺序、主食不放宽、最近结果去重、空题库、随机数可复现。

## 设计说明

- **为什么选 egui**：纯 Rust、无 WebView，`winit + OpenGL` 原生窗口，单文件、依赖只在编译期；比 Tauri/Electron 轻得多。
- **为什么不显示价格**：各平台、各店、各时段价格差异大，程序里的预估价容易误导；价格留给下单平台。
- **为什么不用 AI**：规则筛选 + 轻度随机足够解决「选择困难」，离线、可解释、不花钱。
- **位置/外卖平台**：美团、饿了么/淘宝闪购、京东秒送的菜单接口都是 B 端开放平台，需要企业资质、AppKey 和商户授权，没有面向个人的「城市 → 全城菜单」公开接口；因此用 `menu.txt` 承载你附近的真实菜单，保持离线。
